DEPLOYMENT GUIDE

ElectionLab

Public siteAdmin
ABOUT 15–25 MINUTES

Put ElectionLab online

The code is finished. These steps connect it to accounts that belong to you, so nobody else—including me—has your password or secret keys.

1

Create a Supabase project

Create a new project. In the project dashboard, open the SQL Editor, paste all of supabase/schema.sql, and run it.

2

Create your admin account

In Supabase, open Authentication → Users and create a user using your email and a strong password. Copy that user’s UUID. In SQL Editor, run:

insert into public.admins (user_id)
values ('PASTE-YOUR-AUTH-USER-UUID-HERE');

Do not enable open public sign-ups. The app has no sign-up screen.

3

Connect the website

Open config.js in Notepad. Paste your project URL and your publishable/anon key. Never use the service_role or secret key in browser files.

window.ELECTIONLAB_CONFIG = {
  supabaseUrl: "https://YOUR-PROJECT.supabase.co",
  supabaseAnonKey: "YOUR-PUBLISHABLE-OR-ANON-KEY"
};
4

Test locally

Open admin.html, sign in, save a draft, and publish it. Then open index.html. The published forecast should appear. Drafts stay invisible to the public.

5

Deploy with Vercel

Put the folder in a GitHub repository. In Vercel, choose New Project, import that repository, and deploy it as a static site. No build command is required. Vercel will give you a public URL, and future GitHub pushes can deploy automatically.

Security check: public visitors can select only rows whose status is published. Database Row Level Security—not a hidden button—blocks everyone except UUIDs listed in public.admins from writing.

What is already included

Public read-only forecast page, admin login, password reset, drafts, publishing, timestamps, history, restore-as-draft, deletion of drafts, private browser preview, polls, state data, and the original local model studio.
